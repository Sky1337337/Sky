# Підключення Chrome: поведінка та перевірка

`BrowserService.connect()` зберігає підключення Selenium через
`Options.debugger_address` до `127.0.0.1:<порт із налаштувань>`.
Портал під час підключення не відкривається.

## Очікування та повторні спроби

- Підготовка ChromeDriver виконується один раз на виклик, із лімітом 30 с
  та окремим повідомленням у журналі. Помилка завантаження дозволяє повторити
  підключення.
- Після підготовки діє спільний ліміт 30 с для готовності DevTools та повторів
  Selenium. Перевіряється локальний `/json/version`: відповідь Chrome/Chromium
  має містити WebSocket-адресу DevTools. Проксі операційної системи не потрібен.
  Кожна перевірка обмежена 1 с, інтервал повторів — до 0,5 с із урахуванням
  залишку часу. Швидкий запуск не потребує обов'язкової паузи.
- Готовий відладочний Chrome використовується повторно. Якщо запущений цією
  службою процес на тому самому порту ще працює, повторне підключення чекає його
  готовності. Усередині циклу повторів `Popen()` не викликається.
- Після тимчасової `WebDriverException` створюється нова служба ChromeDriver,
  але Chrome повторно не запускається. Невдалі служби зупиняються. Завислий
  виклик Selenium також обмежений залишком часу; пізній результат не стає
  активним драйвером і його служба прибирається.
- Попередня служба ChromeDriver від'єднується без `driver.quit()`, щоб залишити
  Chrome та вкладки відкритими. Очікування від'єднання обмежене 1 с. Отже,
  підготовка та власне підключення мають окремі ліміти; 30 с не є загальним
  лімітом першого завантаження драйвера разом із запуском Chrome.
- При остаточній помилці `self.driver` залишається `None`, повідомлення вказує
  адресу, етап, ліміт і кількість спроб Selenium та пропонує повторити
  підключення. Наявний `_connect_worker()` передає повідомлення й результат у
  чергу UI. Позиції обробки Excel не скидаються.

## Автоматичні перевірки без порталу

Із папки `Detective_Portal`:

```console
python -m pip install -r requirements.txt pytest
python -m pytest -q tests/test_browser_service.py
python -m pytest -q
python -m compileall -q browser_service.py ui.py tests
```

Тести служби не потребують дисплея, Chrome або завантаження ChromeDriver:
процеси, HTTP, інсталятор і Selenium підмінені. Годинник імітує готовність через
4,5 с, тимчасову помилку Selenium, відсутність порту, постійну помилку та
успішне повторне підключення. Перевіряються також завислі залежності, прибирання
пізнього драйвера, повторне використання процесу й коректність DevTools JSON.
Тест UI перевіряє журнал і зміну стану «помилка → повтор → підключено» через
справжні робочі потоки та чергу подій із підміненим браузером.

Для повного набору UI-тестів потрібен графічний дисплей; у Linux можна
використати `xvfb-run -a python -m pytest -q`.

Результат 20 жовтня 2026 року: **83 тести пройшли** в Linux із віртуальним
дисплеєм Xvfb, Python 3.12.14, Selenium 4.51.0 та CustomTkinter 6.0.0.
Окремо успішно виконано `compileall` і `git diff --check`.
Справжні Chrome, ChromeDriver і портал у перевірках не використовувалися.

## Окрема перевірка Windows

Нативний Windows та справжній запуск Chrome у середовищі цієї розробки
недоступні. Наведені нижче кроки — план перевірки, а не звіт про виконання
на Windows. Жоден крок не потребує звернення до реального порталу.

У PowerShell, із папки `Detective_Portal`, для Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt pytest
.\.venv\Scripts\python.exe -m pytest -q tests/test_browser_service.py tests/test_ui.py
.\.venv\Scripts\python.exe main.py
```

1. Натиснути «Підключити Chrome», залишивши в браузері `about:blank`.
   Очікувати повідомлення про готовність DevTools і підключення Selenium.
   Першому запуску може знадобитися мережа для підготовки ChromeDriver.
2. Повторити підключення: уже відкриті вкладки повинні зберегтися. У диспетчері
   завдань перевірити основний процес Chrome із профілем
   `%USERPROFILE%\AppData\Local\DetectivePortalPro\ChromeProfile`;
   звичайні дочірні процеси Chrome не є додатковими екземплярами браузера.
3. На машині з повільним запуском понад 3 с перевірити успіх до закінчення
   30-секундного вікна готовності. Керований сценарій затримки 4,5 с та
   тимчасова помилка Selenium окремо перевіряються автоматичними тестами вище.
4. Для відмови закрити лише Chrome з профілем програми, зайняти налаштований
   порт локальним сервером, наприклад
   `.\.venv\Scripts\python.exe -m http.server 9222 --bind 127.0.0.1`,
   і повторити підключення. Чужа HTTP-відповідь не повинна вважатися DevTools;
   після ліміту UI має показати зрозумілу помилку та залишатися доступним.
5. Зупинити локальний сервер і закрити Chrome з профілем програми, запущений
   у невдалій спробі. Повторити підключення без перезапуску Helper НПУ:
   воно має завершитися успішно. Зафіксувати версії Windows, Python, Chrome,
   Selenium, ChromeDriver та повідомлення журналу.
